# 工具

本仓库**只出规范、不出软件**（见根 README「本仓库的边界」）。
这里放的是**维护规范本身**用的工具——它们不实现规范，只检查规范写对没有。

---

## 常设：自检闸

```bash
python tools/audit.py
```

离线、一条命令、失败返回非零退出码——对应《模块纪律》对构建期门禁的四条要求
（`BT-1` 最小集 / `BT-2` 一条命令+非零退出 / `BT-3` 阻断合并 / `BT-4` 离线可跑）。
**改完任何文档都应该跑一遍。**

### 检查什么

| 项 | 内容 | 级别 |
|---|---|---|
| **A 相对链接** | 链接目标必须存在 | ERROR |
| **B 标题锚点** | `](#anchor)` 必须与某个真实标题对得上（GitHub 规则：去标点、空格转 `-`、转小写） | ERROR |
| **C 节引用** | `§N` 必须指向 `docs/framework.md` 里真实存在的节 | ERROR |
| **D 条款编号** | 前缀**必须有唯一归属**（撞号即 ERROR）；编号必须有定义 | ERROR / WARNING |
| **E 编码** | 无 BOM、无替换字符 `U+FFFD` | ERROR |
| **F 已删产物** | 不得引用已移除的 `reference/` 与 `conformance/` | WARNING |

`docs/reviews/` 下的历史记录不参与规范性检查——它们描述的是"当时的状态"。

### 条款编号的登记制度

每份文档头部有一行机读登记表，声明**本文档拥有哪些条款前缀**：

```markdown
<!-- clauses: ST AT ID CC AU EX BD RP MI NL XAD DF FD -->
```

规则：**一个前缀只能登记在一个文件里。** 重复登记会被审计判为 ERROR。

> 这条制度来自一次实测教训：框架的 `A-1`~`A-5`（Agent-first）与《模块纪律》和 I4 的
> `A-1`~`A-4`（原子纪律 / 原子性）同号，三处都短到无法自辨。
> 靠人记约定不可靠，所以让机器查。
>
> 框架的 `G-`（治理）是**唯一保留的例外**：外部 Issue/讨论可能已引用它，
> 改名代价大于收益，改为在框架 §25 与 `CONTRIBUTING.md` 用文字限定文档名。

新增前缀时要做两件事：**① 在文档登记表里声明；② 加进 `audit.py` 的 `DECLARED_PREFIXES`。**

## `_migrations/`：一次性迁移脚本（已执行完，留作审计线索）

这些脚本**已经跑过了**，不是常设工具。留着是为了让"文档是怎么被机械改的"可复核——
节号和引用是脚本改的，不是我手打的。

| 脚本 | 做了什么 |
|---|---|
| `restructure_five_elements.py` | 把 `framework.md` 骨架从"层/接口/治理"重排为**五要素**主轴；含节号唯一性校验与幂等保护 |
| `fix_section_refs.py` | 节号顺延 +5 后，修正**指向框架**的交叉引用（不误伤 spec 内部节号） |
| `detach_impl_refs.py` | 删除 `reference/` 与 `conformance/` 后，把指向已删产物的措辞降级为自洽表述 |
| `rename_e_clause.py` | 框架要素条款 `E-1`~`E-8` → `ELE-1`~`ELE-8`（避开 I4 的表达式语言组） |
| `disambiguate_clause_ids.py` | 框架 Agent-first 组 `A-n` → `AG-n`；补三处跨文档限定 |
| `unify_object_term.py` | 正文"概念" → "对象"（五要素口径），保留 Ossie 载体名与接口签名 |
| `disambiguate_spec_prefixes.py` | 消解 spec 之间的条款前缀撞号（268 处） |
| `fix_prefix_residue.py` | 补掉上一脚本留下的两处残余撞号（`DF`/`BG`/`BD`） |

**⚠️ 它们大多带幂等保护**（检测到已执行会拒绝重复运行），且**不应再对当前文档执行**——
文档结构已经变了，脚本里的行号锚点会失效。

## 两个可直接借用的结论

1. **机械改文档要"先干跑、再校验、后落盘"**。本次重排中，脚本自带的两个校验抓出了
   "同一规则套用两遍"的 bug（标题被顺延脚本二次改写）——手改绝对发现不了。
2. **命名后必须对着全表查重**，不要逐个判断"这个名字应该没人用"。
   `disambiguate_spec_prefixes` 之后仍撞了两次（`DF-`、`BD-`），都是这个原因。
